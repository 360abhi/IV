Process: a running program
it has : PID,memory,cpu usage,owner

Thread : small unit inside process ( like browser having many tabs )
Process has its own memory space, while threads share same memory inside the process

Process states:
| State | Meaning        |
| ----- | -------------- |
| R     | Running        |
| S     | Sleeping       |
| D     | Waiting on I/O |
| Z     | Zombie         |

Zombie Process: process finished execution but parent did not collect exit status, still in process table
uses no cpu, no memory but still occupies a PID - > Kill parent process, not zombie
ps - > process status
It shows a snapshot of currently running processes at the moment you run the command (unlike top/htop, which are live)
ps -f : full format : uid ,ppid,start time
** ps -ef : all process, full details : zombie

ps aux : all users process,cpu and memory usage,commands with arguments
** ps -elf | grep Z : lists all Z process from all running process [ ps -elf | awk '$2=="Z"' ]
kill pid : kill process
kill -9 pid: force kill

* top -> live system view : cpu , memory, load, top process

** CRON
Cron job : A Scheduled task that runs automatically at fixed time
Cron = background scheduler

Cron Daemon :
Cron is handled by crond service
Runs in background
Executes tasks silently

* * * * * command
| | | | |
| | | | └─ Day of week (0-7, Sun)
| | | └── Month (1-12)
| | └─── Day of month (1-31)
| └──── Hour (0-23)
└────── Minute (0-59)

Run script every day at 2 AM
0 2 * * * /home/user/backup.sh

| Task           | Cron          |
| -------------- | ------------- |
| Every minute   | `* * * * *`   |
| Every day 2 AM | `0 2 * * *`   |
| Every Sunday   | `0 3 * * 0`   |
| Every 5 mins   | `*/5 * * * *` |
| Weekdays       | `0 9 * * 1-5` |

*/5 * * * *
0,5,10,15 * * * *
They mean the same thing

/5 means every 5 units

============ Scenarios=================

Your application is not responding. What do you do?

Check if process is running
ps -ef | grep app

Check CPU / memory
top

Check logs
tail -f /var/log/app.log

Restart or kill safely
kill PID

Disk is 100% full. App stopped


Check disk:
df -h

Find culprit:
du -sh /var/*

Clear logs safely:
> app.log

Cron didn’t run. What do you check?

Is cron present?
crontab -l

Script executable?

chmod +x script.sh
Absolute paths used?
Logs redirected?
Cron service running? : systemctl status crond
Cron logs : /var/log/cron
