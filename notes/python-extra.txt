2. Python Memory Management
Garbage Collection
Reference Counting: Each object has counter of references; when zero, memory freed

Generational GC: Python uses generational garbage collection (young, old generations)

Cyclic References: Reference counting fails here → generational GC handles

python
# Reference counting example
import sys
a = []  # Ref count = 1
b = a   # Ref count = 2 (a and b refer to same list)
sys.getrefcount(a)  # Returns ~3 (temporary ref during call)
del b   # Ref count = 1
del a   # Ref count = 0 → garbage collected
Interview Q: "How does Python manage memory?"
Answer: "Python uses reference counting for immediate cleanup and generational garbage collection for cyclic references. Objects are stored in a private heap managed by Python memory manager."

3. Mutable vs Immutable Types
Critical Distinction
Mutable (can change)	Immutable (cannot change)
list, dict, set	int, float, str, tuple, frozenset
x = [1,2]; x[0] = 9 ✓	x = (1,2); x[0] = 9 ✗
python
# Immutable - creates new object
a = "hello"
print(id(a))  # Memory address
a += " world"  # Creates NEW string
print(id(a))  # Different address!

# Mutable - modifies in place
b = [1, 2, 3]
print(id(b))
b.append(4)   # Same object
print(id(b))  # Same address
Interview Q: "Why does this happen?"

python
def modify_list(lst):
    lst.append(4)
    
my_list = [1, 2, 3]
modify_list(my_list)
print(my_list)  # [1, 2, 3, 4] ← CHANGED!

def modify_string(s):
    s += " world"
    
my_str = "hello"
modify_string(my_str)
print(my_str)  # "hello" ← NOT changed!
Answer: "Lists are mutable, so function modifies original. Strings are immutable, function creates new string that's discarded. This affects how we write test data setup/teardown."

4. Python Data Structures - When to Use What
Most Asked: "Difference between list, tuple, set, dict?"
python
# LIST: Ordered, mutable, allows duplicates
test_cases = ["test1", "test2", "test1"]  # OK

# TUPLE: Ordered, immutable, allows duplicates
config = ("localhost", 8080)  # Good for constants

# SET: Unordered, mutable, NO duplicates, fast membership test
unique_errors = {"404", "500", "502"}  # Automatic deduplication

# DICT: Key-value pairs, keys must be immutable
test_data = {"username": "test", "password": "pass123"}
Pro Tip: "In testing, use tuples for test data that shouldn't change, sets for unique error codes, dicts for JSON-like test data, lists for ordered test steps."

5. List Comprehensions vs Generator Expressions
Memory Efficiency
python
# List comprehension - creates FULL list in memory
squares = [x**2 for x in range(1000000)]  # Uses ~8MB

# Generator expression - lazy evaluation
squares_gen = (x**2 for x in range(1000000))  # Uses few bytes
print(next(squares_gen))  # 0
print(next(squares_gen))  # 1

# Useful for large test data
def read_large_file(file):
    return (line.strip() for line in file)  # Generator, not list
Interview Q: "When would you use generator?"
Answer: "When processing large files in testing - like parsing 10GB log files on 2GB RAM. Generators process one item at a time, saving memory."

6. Decorators (Common in Testing Frameworks)
What are Decorators?
Functions that modify other functions. Common in testing:

python
import time

def timer(func):
    def wrapper(*args, **kwargs):
        start = time.time()
        result = func(*args, **kwargs)
        end = time.time()
        print(f"{func.__name__} took {end-start:.2f} seconds")
        return result
    return wrapper

@timer
def run_long_test():
    time.sleep(2)
    return "Test passed"

run_long_test()  # Prints: run_long_test took 2.00 seconds
Real Testing Example
python
def retry_on_failure(max_attempts=3):
    def decorator(func):
        def wrapper(*args, **kwargs):
            for attempt in range(max_attempts):
                try:
                    return func(*args, **kwargs)
                except Exception as e:
                    if attempt == max_attempts - 1:
                        raise
                    print(f"Retry {attempt + 1}/{max_attempts}")
            return None
        return wrapper
    return decorator

@retry_on_failure(max_attempts=3)
def flaky_api_call():
    # Sometimes fails, needs retry
    pass
Interview Q: "What are decorators?"
Answer: "Functions that wrap other functions to add behavior without modifying them. In testing, we use them for retry logic, timing, logging, and setup/teardown."

10. Exception Handling in Tests
Testing Exceptions
python
import pytest

def test_division_by_zero():
    with pytest.raises(ZeroDivisionError) as exc_info:
        result = 1 / 0
    assert str(exc_info.value) == "division by zero"

# Custom exception testing
class ValidationError(Exception):
    pass

def validate_age(age):
    if age < 0:
        raise ValidationError("Age cannot be negative")

def test_negative_age():
    with pytest.raises(ValidationError) as exc:
        validate_age(-5)
    assert "cannot be negative" in str(exc.value)
Try-Except-Else-Finally
python
def safe_file_read(filename):
    try:
        f = open(filename, 'r')
    except FileNotFoundError:
        print("Test file missing, using default")
        data = "default"
    except PermissionError:
        print("No read permission")
        data = ""
    else:
        # Runs ONLY if no exception
        data = f.read()
        f.close()
    finally:
        # ALWAYS runs (cleanup)
        print("Cleanup complete")
    return data
Interview Q: "How do you test error conditions?"
Answer: "Use pytest.raises() to verify exceptions are thrown. Also test error messages and edge cases like network failures, invalid inputs, and boundary conditions."

11. Duck Typing & Polymorphism
Testing Concept
python
# Duck typing: "If it quacks like a duck, it's a duck"
class MockResponse:
    """Mimics real response for testing"""
    def __init__(self, status_code=200, text=""):
        self.status_code = status_code
        self.text = text
    
    def json(self):
        return {"status": "ok"}

# Function doesn't care about class, only interface
def process_response(response):
    if response.status_code == 200:
        return response.json()
    return None

# Works with both real and mock!
real = requests.get(url)
mock = MockResponse(status_code=200)
process_response(real)  # Works
process_response(mock)  # Also works!
Interview Q: "What is duck typing?"
Answer: "Python doesn't check object type, only if it has required methods/properties. Great for mocking in tests - we can create simple test doubles that mimic real objects."

13. Python's GIL (Global Interpreter Lock)
SDET Perspective
What is GIL?: Only one thread executes Python bytecode at a time, even on multi-core.

Impact on Testing:

I/O-bound tests (API calls, DB queries): Threading helps (GIL released during I/O)

CPU-bound tests (data processing): Use multiprocessing, not threading

python

def run_test(test_data):
    # CPU-intensive test

with Pool(processes=4) as pool:

Interview Q: "Does Python support multithreading for performance?"
Answer: "For I/O-bound tasks like API testing - yes, threads work well since GIL is released during I/O waits. For CPU-bound tasks like data validation, use multiprocessing instead."

14. Most Common Python Interview Questions (Non-Coding)
Q1: "What are Python decorators and give a testing example?"
Answer: "Functions that modify other functions. In testing: @pytest.fixture for setup, @retry for flaky tests, @mock.patch for mocking."

Q2: "Difference between __init__ and __new__?"
Answer: "__new__ creates the object (constructor), __init__ initializes it. Rarely override __new__ except for singletons or immutable objects."

Q3: "What is if __name__ == '__main__'?"
Answer: "Code only runs if file is executed directly, not imported. Useful for test runners:"

python
if __name__ == "__main__":
    pytest.main([__file__])  # Run tests when script executed
Q4: "How are Python dictionaries implemented?"
Answer: "Hash tables with dynamic resizing. Average O(1) lookup. Keys must be hashable (immutable)."

Q5: "What is monkey patching?"
Answer: "Dynamically modifying classes/modules at runtime. Useful in testing to replace real implementations with mocks:"

python
import module_to_test

def mock_function():
    return "test data"

module_to_test.real_function = mock_function  # Monkey patch!
Q6: "Explain Python's method resolution order (MRO)"
Answer: "In multiple inheritance, Python uses C3 linearization. Check with ClassName.__mro__. Ensures consistent order of method lookup."
